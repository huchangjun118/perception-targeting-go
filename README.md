# perception-targeting-go

面向场景仿真的进程内感知评估与目标选择系统。多个代理在同一场景中互相感知，
处理遮挡、传感器噪声、丢帧与记忆衰减，并以确定、可复现、可解释的方式完成
威胁评分与目标分配。不依赖任何外部服务，场景与传感器输入全部由内存对象
或本地 JSON 文件模拟。

## 包结构

| 包 | 职责 |
|---|---|
| `geom` | 二维向量、射线-线段/圆求交、视线遮挡判定 |
| `perception` | 传感器建模、多传感器融合快照、感知记忆与衰减 |
| `targeting` | 威胁评分、目标选择、目标声明（占用/抢占/释放） |
| `sim` | 场景定义与确定性并发推进引擎 |
| `config` | 场景配置的版本化序列化、迁移与校验 |

## 感知语义

### 传感器

每个代理可配置多个传感器（`SensorConfig`）：

| 字段 | 含义 |
|---|---|
| `id` | 传感器标识（同一代理内唯一） |
| `fov_deg` | 视场角（度），`(0, 360]`，360 为全向 |
| `range` | 量程（米） |
| `rate_hz` | 更新频率；低于全局步频时按 `floor(tick*rate/stepHz)` 递增规则确定更新帧 |
| `noise_std_pos` | 位置噪声标准差（米，高斯） |
| `drop_prob` | 单次扫描丢帧概率 `[0,1]` |
| `mount_offset` | 相对代理朝向的安装偏角（弧度） |

### 可见性等级

对目标圆盘采样三条视线（中心 + 左右边缘，边缘向内收缩 1e-6 使切线判定确定）：

- `full`：三条视线均通视；
- `partial`：部分视线被遮挡；
- `invisible`：全部遮挡或超出视场/量程，不产生观测。

静态障碍（线段）与动态物体（圆）都会遮挡视线；目标自身与感知者自身不计入遮挡。
几何判定使用统一容差 `eps=1e-9`，边界情况（平行、切线、端点）结果确定。

### 融合快照

同一帧内所有传感器的观测按目标融合为一份快照（`Snapshot`）：

- 位置按传感器权重 `1/(1+noise_std)` 加权平均；
- 可见性取各传感器中的最高等级；
- `contributors` 列出贡献传感器 ID（排序），保证可解释；
- 置信度由贡献者数量与可见性等级决定；
- 目标列表按 ID 排序，帧输出与遍历顺序无关。

### 感知记忆

目标离开视野后按 `ttl_ticks` 保留记忆，规则确定：

- `now - last_seen >= ttl_ticks` 即过期，过期条目不参与决策；
- 未被观测的条目每帧置信度乘以 `decay`；
- 迟到信息（`last_seen` 早于现有条目）被拒绝，不得覆盖较新记忆。

## 评分与目标选择

候选目标按五项归一化分项加权求和（权重均可配置，`ScoreWeights`）：

| 分项 | 规则 |
|---|---|
| `distance` | `1 - d/max_range`，越近越高 |
| `heading` | `1 - |bearing|/π`，越朝向代理越高 |
| `persist` | `p/(p+10)`，持续可见越久越高，平滑饱和 |
| `threat` | 目标固有威胁度 `[0,1]` |
| `confidence` | 当前记忆置信度 |

平局裁决确定：分差 `< 1e-9` 视为平局，选目标 ID 字典序最小者。
每次选择都返回 `Decision{TargetID, Score, Reason}`，`Reason` 说明评分与裁决依据。

## 目标声明与抢占

`ClaimRegistry` 保证任一目标同一时刻至多被一个代理占用：

- 目标空闲或已被自己占用 → 声明成功；
- 被他人占用时，挑战者评分高于占用者 `1e-9` 以上才抢占；
- 评分平局时，代理 ID 字典序小者优先；
- 仅占用者可释放；代理切换目标或失去所有候选时自动释放旧声明。

## 并发推进与确定性

引擎每帧分三个阶段：

1. **感知**（并发）：各代理独立扫描与融合，写入各自槽位；每个代理持有
   独立随机源（`seed + agentIndex*7919`），随机数消耗顺序与调度无关；
2. **决策与声明**（串行）：按代理 ID 排序依次更新记忆、评分、选择、声明；
3. **世界推进**：目标按速度确定性移动。

因此固定随机种子与相同输入序列下，逐帧快照与目标选择结果逐条一致，
与 worker 数、调度顺序无关（有测试覆盖：1 与 16 worker 结果完全相同）。
慢代理只会拉长其所在帧的感知阶段，不会阻塞其他帧或破坏结果。

## 配置序列化与版本

`config.Marshal/Unmarshal` 使用版本化信封 `{"version": N, "scene": {...}}`：

- 当前版本为 2；v1 数据缺少 `drop_prob`/`decay`/`max_range`，
  迁移时填充确定默认值（`decay=0.95`、`max_range=100`），升级后结果等价；
- 高于支持版本的数据被拒绝；
- 错误类别可区分：`malformed`（JSON 无法解析）、`unsupported`（版本不支持）、
  `validation`（字段非法或残缺，错误信息指明具体字段）。

## 运行测试

```sh
go test ./...          # 全部单元与集成测试
go test -race ./...    # 竞态检测
go test ./sim/ -bench=. # 大规模推进基准
```

测试覆盖：遮挡（静态/动态/部分可见）、噪声与丢帧、记忆过期与迟到拒绝、
评分平局裁决、目标抢占与释放、并发推进确定性、序列化回放等价。
